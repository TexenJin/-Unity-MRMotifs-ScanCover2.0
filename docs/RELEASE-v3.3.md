# v3.3 — CHSL 分片调度与保守拓扑检查点

存档日期：2026-10-21

## 定位

`v3.3` 是 Quest 3 实时深度建网研究路线的可回退检查点，不是生产完成版。
它保留原生产网格，同时以完全隔离的 CHSL 旁路验证 5 cm 稀疏 TSDF、
15 cm 截断带、Marching Cubes 出网以及写入前的保守观测处理。

## 本检查点已经确认的成果

- 深度、同帧时间/位姿/重投影矩阵以双眼配对观测进入 CHSL 路线。
- CHSL 使用独立的空间哈希块和 TSDF，不读写原生产 TSDF 与发布状态。
- 深度断层保护、稳定表面观测关联、方向所有权、有限最大权重和双眼连续确认的自由空间修复均已接入。
- 远处细节不再被全局统一降采样明显抹掉；转角假桥及墙后大规模乱网、浮空岛相较早期版本显著减少。
- Marching Cubes 改为块内共享边顶点并去除重复线段，降低了线框顶点和索引开销。
- 双眼解码、深度连续性、法线、遮挡射线、候选块发现、候选晋级/过期和 TSDF 融合均改为预算分片执行。
- 实机确认第一阶段目标达成：原先约 135 ms 的单帧主线程停顿被拆开，HUD 单片峰值约 4.1 ms；冻结后网格稳定，MC 队列能够排空。

## 已知边界（后续工作入口）

- 一对双眼观测的累计 CPU 工作量仍可达到约 217 ms；分片解决了卡顿，但尚未解决端到端延迟。
- 当前候选块仍明显过宽：一次实机记录为 `proj=71/393`，大量候选块完成扫描却没有写入。
- 新表面默认需要 3 对确认；促成晋级的当前观测尚不能立即写入 TSDF，还需等待下一对观测。
- Marching Cubes 要求一个单元的八个角全部达到网格权重阈值，因此新区域常先以破洞较多的片区出现，再由后续观测补齐。
- 新区域不能做到转头后立即跟随成片长出；应先修复“同对晋级即写入”、候选块精确裁剪和成熟前沿优先级，再考虑提高捕获频率。
- 墙角交汇处仍可能形成难以快速消退的凸楞；不得通过降低网格权重、允许缺角出网或关闭深度断层保护来掩盖。
- 本 tag 不代表 Plane Priors、房间理解或结构化覆盖网格已经完成。
