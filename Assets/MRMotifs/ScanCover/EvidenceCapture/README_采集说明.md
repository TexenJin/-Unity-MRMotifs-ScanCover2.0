# Quest 深度证据采集 Scene

这张 Scene 只负责保存可复算的 Quest 3 实机证据，不运行 ScanCover 网格、TSDF、DMC、影子链或离线对照。旧采集工具只作为 API 参考，没有被继承进来。

## 画面操作

- `B`：开始一轮记录；也可在计时结束前手动停止。
- 编辑器备用键：`F9` 开始/停止。

HUD 固定三行，只显示状态、90 秒倒计时、帧数、已写数量、队列、系统提示和启停键。采集者不需要也不能人工标注结构或异常。队列拥堵时暂停新采样，不会假装采到或静默丢帧。计时到 90 秒后会自动停止新增采样，并等待在途 GPU 回读和写盘完成；要等 HUD 从“保存中”变成“本轮已完整保存”再退出应用。

## 每帧保存什么

权威输入是 `raw_depth_r32f` 与同帧矩阵/位姿。其余缓冲是同一份冻结输入在 Quest GPU 上即时生成的跨实现证据：

1. 双眼原始 `depth01`，完整分辨率；先在 GPU 结构化缓冲中按左眼、右眼顺序展开，再完整回读。
2. 相机 Z、径向距离、有效位。
3. 原始世界点与原始 GPU 法线。
4. 保守邻域世界点与邻域法线；它们不是训练真值，只用于复核实机派生过程。
5. 邻域最大深度跳变、邻居支持率和边缘风险。
6. Meta 重投影矩阵及逆矩阵、双眼 view/projection、camera-to-world/world-to-camera、near/far Z、FOV、画面尺寸。
7. 请求时与 GPU 回读完成时的相机位姿，以及头、中心眼、左右眼的跟踪状态、位置、旋转、速度、角速度。
8. Unity 帧号、UTC、realtime、DSP time、GPU 回读延迟、设备/图形 API/工程版本。
9. 可供离线程序自动划分距离、运动、结构与异常区间的完整原始量；不写人工结构/异常标签。

深度噪声、空洞、跳变和有限的远距异常只记录，不用人为 near/far 门槛提前清零；但证据结构和 GPU 派生语义必须完整。只要发现深度纹理不是双眼数组、任一眼完全无有效深度、任一缓冲层数或字节数错误，或抽样复算发现“原始深度本应有效却被 GPU 清零 / 世界点与径向距离不一致”，本轮就立即停止并明确判定失败，残缺帧不会写成成功证据。Meta 当前未提供可靠的传感器原生 frame id 和 sensor timestamp，因此文件中明确标为不可用，不能用 Unity 帧号冒充。

## 输出位置与恢复能力

Quest 内部目录：

`Application.persistentDataPath/ScanCoverDepthEvidence/Evidence_yyyyMMdd_HHmmss_fff`

会话包含：

- `session.json`：设备、工程版本、配置与缓冲说明。
- `manifest.csv`：每帧状态、哈希和基础深度/有效率统计。
- `frames/frame_XXXXXXX.scede`：独立、可恢复的证据帧。
- `checksums.sha256`：逐帧 SHA-256。
- `capture_audit.json`：正常收尾后的总数与失败数。
- `runtime_summary.json`：本轮最终成败、首个致命原因、请求/写入帧数和 GPU 完整性计数。

每个缓冲另带 CRC32。单帧写入先落到 `.tmp`，成功后才原子改名，因此断电或应用中断不会把半个文件伪装成有效帧。

## 第一轮门禁采集

每轮固定采集 90 秒，不要一上来连续采整屋。按 `B` 后自然观察周围，允许静止、转头和走动，不需要按场景类别分段，也不要人工判断坏帧；90 秒到时会自动停止并存盘，也可提前再次按 `B` 手动停止。等待 HUD 显示完整保存后再导出会话。

距离、运动模式、空洞、跳变、双眼差异、法线异常和候选结构区间统一由离线程序从深度、矩阵、位姿和时间序列中自动计算。

短采必须满足：帧号连续、`failedFrames=0`、SHA/CRC 全通过、左右眼有效率非零、矩阵和位姿存在、重复原始帧能被统计出来。通过后才扩大到多房间和困难材质。

```powershell
python Assets/MRMotifs/ScanCover/EvidenceCapture/Tools/validate_evidence_session.py "会话目录" --write-report
```
